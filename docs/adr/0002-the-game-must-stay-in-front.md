# The game must stay in front

The app does not fish in a window that is not in front. Capture (Windows Graphics Capture) and the game's sound work in the background, but input does not: the Board is a real USB keyboard and mouse, and Windows routes hardware input only to the foreground window, so a key it sends while the player works elsewhere lands in the player's app (see 0001 for why there is no software input). A run therefore needs the game in front for its whole length, not only at a cast or reel, and pauses whenever it loses focus. Bringing the game forward just before each input was rejected both ways: through the Board (a click on the game or Alt+Tab), because that input goes to whichever app is in front and takes the player's keyboard and pointer several times a minute; and through the app (`SetForegroundWindow` and similar), because Windows' foreground lock often refuses it and it takes focus from the player just the same. To fish in the background, run the game and the app on a second PC or a VM with the Board plugged in there, where the game stays in front; the app needs nothing for that.
