title: "Configuration"
summary: "Every setting in pixle_bot_config.json, its default and its limits."
order: 2
---

| Setting                     | Meaning                                     | Tradeoff                               |
| --------------------------- | ------------------------------------------- | -------------------------------------- |
| CastKey (`cast_key`)        | Unmodified key that casts: F1 to F12, a letter, a top-row digit, `Mouse4` or `Mouse5` | An unknown key halts the run           |
| WaterBuff (`water_buff`) | Water buff Bobber Marker keeps up through the Cast macro: `water_walking` (spell 546), `levitate` (1706) or `elixir_water_walking` (item 8827, aura 11319) | Empty (off) by default; any other value resets to empty. Sent in `Keys.lua` as `buff`. The addon checks the aura on `UNIT_AURA` and every 5 s; with under 45 s left and the spell usable (or the elixir in the bags) it rewrites the Cast macro to cast the buff, then back to Fishing once the buff is up. That cast brings no bobber, so the run counts one failed cast, which the next catch resets. Macros cannot change in combat, so a swap waits for combat to end |
| ReelMethod (`reel_method`)  | How to interact with the bobber             | `right_click` by default, or `interact_key` with the marker locator |
| InteractKey (`interact_key`) | Native Interact binding for key-based reeling, using the same supported keys as CastKey | F10 by default; the addon binds it only with the Interact reel. Key-based reeling requires a binding distinct from Cast and Stop. |
| ESP32Port (`esp32_port`) | Serial port for the ESP32 BLE keyboard and mouse, such as `COM3`, or `auto` | Required for live input; an empty setting prevents a live run. `auto` tries each USB serial port with the firmware handshake and uses the first that answers. Keys go through the board as HID taps, and pointer movement and right-click reeling require firmware that answers `POINTER`. Mouse 4 and 5 bindings require firmware that answers `BUTTONS`. |
| Reposition (`reposition`) | Movement script after 45–55 acknowledged reels | Off by default. Presses W, A, S or D through `activity`, and drags the camera through ESP32 firmware that answers `MOUSE`. Requires the Logout key, which a failed sequence uses. Replaces `reposition_key`. |
| IdleMoves (`idle_moves`) | Between-catch movement, after every cooldown | Off by default. A camera nudge (one in four, where `DragCamera` fits; the next nudge turns the last one back) or a pointer path from `Pointer.Pos`: a wander along `wanderPath`, or one in `swirlOdds` a `swirlPath` round the game window. The path runs in timed steps on the cooldown's deadline (`startIdle`, `idleStep`), so any transition ends it. Pointer moves only, never a button. Replaces `idle_key`. |
| MaxFailedCasts              | Casts in a row without a reel before halting | Default 5                             |
| MaxSessionMinutes           | Run length; halts at the next cast after it | Default 60                             |
| Schedule (`schedule`)      | Alternate scheduled play and logged-out breaks | Off by default |
| PlayMinMinutes / PlayMaxMinutes (`play_min_minutes`, `play_max_minutes`) | Inclusive play duration bounds | 20 and 45 minutes by default |
| BreakMinMinutes / BreakMaxMinutes (`break_min_minutes`, `break_max_minutes`) | Inclusive logged-out duration bounds | 5 and 15 minutes by default |
| LogoutKey (`logout_key`) | Key the addon binds to its `Logout` macro (`/logout`), sent in `Keys.lua` while `schedule` or `reposition` is on | Checked when a run starts with breaks or Reposition, not on save, so the switch can go on first. The screen is read from the addon's in-world blocks (`fishing.WorldSignalArea`, `fishing.InWorld`), which replace `character_png` and `in_world_png`. |
| RecordDir (`record_dir`)    | Folder for new recordings                   | Default `datasets`                     |
| RecordKeys (`record_keys`)  | Record keys as well as the mouse            | Default true                           |
| OverlayX / OverlayY (`overlay_x`, `overlay_y`) | Where the overlay pill sits on the game window, each a share of the free space: 0 is the left or top edge, 1 the right or bottom edge | Default 0.5 and 0.01, the top centre; outside 0 to 1 resets to the default. Written by Settings → Overlay → Move overlay (`app/overlay.go`); not a settings form field. The pill is 380 by 44 px in both overlay modes (`app/overlay_place.go`, `frontend/src/overlay.css`) |
| CatchesTotal / FishingSecondsTotal (`catches_total`, `fishing_seconds_total`) | Catches and seconds of fishing on this computer, dry runs excluded | Added when a run ends (`app/support.go`): the fish Bobber Marker reported caught, or the reels with an addon older than 1.5.1; shown on the thank-you card. Not settings form fields |
| SupportMilestone / SupportMuted (`support_milestone`, `support_muted`) | The catch milestone the thank-you card last asked at, and whether the person said they support Go Fish already or not to ask again | The card asks at 100, 500, 1000, 2500, 5000 and every 5000 catches, only after a run with a catch and at most one "not hooked" per four catches (`ui/desktop/support.go`). Older `support_asked_at` and `support_opened_at` are ignored. Not settings form fields |

Set the board and the keys the run uses (Cast, Interact with the Interact reel, Logout with breaks or Change spot) in the setup wizard, or under **Settings**. Defaults: `cast_key` F9, `interact_key` F10, `logout_key` F12. `config.CheckKeys` holds the binding rules, checked on save: a key clashes only with keys the run presses (Interact with the Interact reel, Logout once it is set, W, A, S and D with Change spot). `config.CheckRunKeys` also asks for the Logout key when a run starts with breaks or Change spot.
